# Bingo! 找到彼此的共同點

參考 beauty-game 的 Go + Gin + Gorilla WebSocket、Vue 3 + TypeScript + Vite + Pinia 架構建立的獨立遊戲，包含「互相簽名」、「主持人出題」與「分組輪流出題」三種玩法。

## 開始玩

```bash
./start.sh
```

需要 Go 1.21+、Node.js 20.19+。主板開啟 http://localhost:3345。手機需與電腦同 Wi-Fi，**請用 http://電腦區網IP:3345 開啟主持人頁面**，QR Code 才會帶到手機可達的網址。前端預設 3345、後端 8082，避免與 beauty-game 衝突。

1. 主持人選九宮格或十六宮格、主題、加入方式、目標線數、得獎人數。
2. 內建運動、生活與興趣、認識彼此、美食、旅行、校園生活、職場交流、影視娛樂共 8 組主題，每組 40 題；也可以輸入自訂主題與題目（一行一題，至少 9 / 16 個不重複題目）。後端建房時隨機抽題，之後每個人的題目與位置都固定相同。
3. 加入方式可選「點連結直接加入」或「輸入名字加入」。直接加入會從 20 個形容詞與 30 個動物中產生不重複的隨機暱稱，例如「生氣的獅子」；輸入名字模式允許同名，姓名最多 80 字。一般簽名模式開始後仍可持續掃 QR Code 加入。
4. 玩家點選格子，把手機交給符合描述的朋友。朋友直接在簽名板手寫簽名，不需再輸入姓名；簽名會放大顯示在格子內，確認後此格鎖定。
5. 後端計算橫、直、兩條對角線；主板即時顯示每位玩家進度與各完成線數的人數（互斥分組）。
6. 達成指定線數即得獎，伺服器收到有效簽名的順序决定名次；同一次操作完成多條線也只佔一個名額。主板彈出得獎者、播放 Bong 音效，快速連續得獎會依序公告。主持人可點擊得獎者查看完整簽名板，核對每一格的原始手寫簽名。
7. 主持人可提前結束、結束後再玩一場。再玩時使用原設定重新抽題，玩家身分保留、簽名及名次歸零，回大廳等待主持人開始。

## 分組猜答案

1. 主持人可選大專學校、名人、大台北捷運站、台灣縣市、國家與城市、台灣美食、動物或品牌，並設定 2–12 組。此模式固定使用九宮格。
2. 玩家掃描 QR Code 後會看到 A、B、C…組按鈕，自行選擇組別；每組人數不限。遊戲開始前若選錯，可退出房間並重新選組。
3. 每位玩家在自己的九宮格填寫九個不重複答案；答案最多 40 字，只回傳給玩家本人，主持人只看到是否填滿。
4. 所有人填滿後主持人開始遊戲，口頭說出答案並在主板輸入「公布答案」。玩家輸入及主持人公布時都有內建題庫建議，主持人也可按「隨機帶入」抽出尚未公布的參考答案。
5. 玩家格子與已公布答案相符時會亮起，玩家點擊即可圈選。伺服器會再次核對，未公布的格子不能提前圈選。
6. 橫、直、對角線的連線與得獎名額沿用原本設定，主板會即時顯示組別、圈選格數、線數與名次。

## 分組輪流出題

1. 此玩法固定使用 4 × 4；每位玩家先填入 16 個不重複答案，再由主持人開始遊戲。
2. A、B、C…組依序輪流。輪到的組別可由任一成員從自己的賓果卡選一題提出；第一筆送出的答案會等待主持人審核。
3. 主持人可「通過並公布」、「駁回重選」或「跳過這組」。通過後自動換下一個有玩家的組別，空組會自動略過。
4. 所有玩家都會看到目前組別、待審答案與已公布答案；擁有相同答案的人可一起圈選。
5. 若答案有錯字、簡稱或別名，玩家可提出同答案申請，例如「台彎大學＝台灣大學」或「北大＝台北大學」。申請全房可見，由主持人決定通過或駁回。
6. 同答案申請通過後，相同寫法會對全體玩家生效；主持人另有玩家答案總覽，可在審核時核對每個人的 16 格內容。

## 連線與狀態

- WebSocket 同源連線 `/ws`，每次事件推送最新快照，後端統一判定狀態與名次。
- 主持人、玩家都有獨立隨機憑證；主持人控制不能由玩家冒用。憑證在 WebSocket 訊息中傳送，未放入分享網址。
- 憑證存在分頁 sessionStorage。相同分頁重新整理、短暫斷線都會自動恢復進度。關閉分頁後不保證能恢復；請保持分頁開啟。
- 遊戲開始後不接受新玩家，但既有玩家可重連。未開始、已得獎、已結束或重複簽名都會被後端拒絕。
- 最多 300 人 / 房、500 房。房間無連線且閒置 2 小時後清除。資料只在記憶體，服務重啟會清空；目前應以單一後端實例部署。尚未進行 300 人實際負載測試。
- 圖片簽名不廣播給其他玩家，只隨本人快照保存與恢復。主板看到姓名、在線狀態、格數、線數及名次。

```bash
cd backend

```

## Docker 部署

```bash
cp .env.example .env
# 修改 FRONTEND_URL 為實際 HTTPS 網址
docker compose up -d --build
```

單一容器同時供應前端、API、WebSocket。對外部署時使用支援 WebSocket Upgrade 的 HTTPS 反向代理或 Cloudflare Tunnel，指向 8082。`FRONTEND_URL` 可指定 QR Code 對外網址；未指定時使用瀏覽器當前網址。

正式環境部署在 `https://bingo.ricky-nova.com`，主機對外連接埠為 `20940`。推送到 GitHub `main` 後，GitHub Actions 會先執行後端測試與前端建置，再由專用 self-hosted runner 執行 `/home/ricky/deployments/scripts/deploy-app.sh bingo` 自動更新正式服務。

## 目錄與協定

- `backend/game.go`：題庫、設定驗證、抽題、連線與得獎規則。
- `backend/main.go`：房間、憑證、WebSocket、心跳、過期清理、靜態檔案。
- `frontend/src/store.ts`：Pinia 遊戲狀態、重連、身分恢復。
- `frontend/src/App.vue`：建房、加入、大廳、主板、玩家格子、頒獎。
- `frontend/src/components/SignaturePad.vue`：觸控 / 滑鼠手寫簽名。

客戶端指令：`create {settings}`、`join {room,name,group}`、`resume {room,token}`、`leave`、`start`、`sign {index,signature:{name,ink}}`、`answer {index,value}`、`call {value}`、`propose {index}`、`proposal_decision {id,decision}`、`skip_turn`、`appeal {index,called}`、`appeal_decision {id,decision}`、`claim {index}`、`end`、`reset`。
伺服器事件：`session {room,token,host}`、`state {room,me,host}`、`error {message}`。房間狀態：`lobby → playing → finished → lobby`。
